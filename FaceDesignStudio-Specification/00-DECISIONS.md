# FaceDesign Studio — Decisions and Open Items

این فایل مرجع تصمیم‌های محصول است. هر تصمیمی که روی Scope، داده یا پذیرش عکس اثر می‌گذارد باید اینجا ثبت و در سندهای مرتبط منعکس شود.

## تصمیم‌های قطعی

| موضوع | تصمیم |
|---|---|
| عکس‌برداری | عکس می‌تواند با دوربین داخل اپ گرفته شود یا از Gallery انتخاب شود؛ هر دو منبع باید اعتبارسنجی یکسان شوند. |
| کنترل کیفیت عکس | عکس فقط با عبور از حداقل Confidence تنظیم‌شده پذیرفته می‌شود. مسیر ادامه با عکس مردود وجود ندارد. |
| تنظیم تشخیص | حداقل Confidence پیش‌فرض برنامه ۹۰٪ است و از Settings یا مستقیم در صفحهٔ بررسی چهره تغییر می‌کند؛ مقدار ویرایش‌شده برای تحلیل‌های بعدی باقی می‌ماند. پیش از انتشار با دادهٔ نماینده کالیبره شود. |
| تصویر چندچهره‌ای | به‌جای رد تصویر، Face Detector قوی‌ترین چهره را بر اساس بالاترین Confidence انتخاب می‌کند و Landmarkها روی ناحیهٔ همان چهره محاسبه می‌شوند. |
| پایگاه داده و عکس | اطلاعات برنامه و بایت‌های اصلی عکس به‌صورت BLOB در SQLite محلی ذخیره می‌شوند. Room لایهٔ دسترسی پیاده‌سازی‌شده است. |
| قاعدهٔ Confidence محصول | در صورت استفاده از مدل دارای confidence واقعی برای Landmarkها، میانگین حسابی Face + Landmarkها می‌تواند در نسخهٔ آینده فعال شود. |
| قاعدهٔ Confidence در کد فعلی | آستانه فقط روی امتیاز Face Detector اعمال می‌شود. Landmarkهای ضروری باید حاضر و معتبر باشند، اما confidence آن‌ها وارد شرط پذیرش نمی‌شود. |
| محل اجرا | داده‌ها روی دستگاه و در دیتابیس خود برنامه نگهداری می‌شوند؛ cloud sync جزو Scope فعلی نیست. |
| عکس غیرروبه‌رو | Frontal Score پایین فقط هشدار می‌دهد و ادامهٔ کار را مسدود نمی‌کند. |
| رمزگذاری اضافه | رمزگذاری دیتابیس جداگانه برای Scope فعلی الزام نشده است. |
| ورودی‌های انتخابی | جنسیت در اطلاعات تکمیلی بیمار با گزینه‌های زن، مرد و نامشخص است. الگوی اولیه از سه کارت متعادل، بالاتر و پایین‌تر انتخاب می‌شود؛ روش ترسیم و ارتفاع سفارشی در پنل تنظیمات بیشتر هستند. |
| رابط موبایل | ابزارهای ویرایش در سه پنل نقطه‌ها، ظاهر خط و تراز تصویر قرار می‌گیرند؛ ذخیره مستقیم است و پیش‌نمایش اختیاری. |
| افزودن نقطه | با تقارن و محور معتبر، دو segment متناظر تقسیم می‌شوند و دو نقطهٔ متمایز با حفظ منحنی اضافه می‌شود؛ در حالت مستقل یک نقطه اضافه می‌شود. سقف ۱۲ نقطه است. |
| حرکت نقطه | پس از انتخاب، درگ هر جای کادر عکس حرکت نسبی نقطه را اعمال می‌کند؛ لمس خالی انتخاب را نگه می‌دارد و لغو انتخاب از پنل نقطه‌ها انجام می‌شود. |
| نمایش دستگیره | فقط دستگیره‌های فعال نقطهٔ انتخاب‌شده نمایش داده می‌شوند و قابل لمس‌اند. راهنماها پیش‌فرض خاموش‌اند. |
| ویرایش بیمار | از UPDATE استفاده می‌شود تا عکس‌ها و طرح‌های وابسته حفظ شوند؛ حذف صریح بیمار همچنان cascade است. |
| تغییر آستانهٔ تشخیص | تغییر تنظیم عمومی، طرح جاری را پاک نمی‌کند؛ مقدار استفاده‌شده هنگام تحلیل مستقل از تغییرات بعدی همراه طرح ذخیره می‌شود. |
| حداقل Android و UI | minSdk برابر API 24 و رابط فعلی Compose/Material 3 است؛ بازطراحی نیازمند مهاجرت schema نیست. |
| ادعای پزشکی | خط تولیدشده پیشنهاد برنامه‌ریزی است و تصمیم نهایی با پزشک است؛ برنامه نتیجهٔ قطعی یا تضمین‌شده ادعا نمی‌کند. |

## تصمیم: مدیریت طرح و خروجی — ۲۰۲۶/۱۱/۰۹

- خروجی فایل به PNG تمیز و PNG همراه راهنماها محدود است؛ گزارش PDF و صادرکنندهٔ آن حذف شده‌اند.
- ویرایش یک نسخهٔ ذخیره‌شده، نسخهٔ جدیدی از همان طرح می‌سازد. حذف از کارت، فقط snapshot انتخاب‌شده را پس از تأیید حذف می‌کند؛ عکس فقط در نبود ارجاع دیگر پاک می‌شود.
- خواندن عکس بزرگ برای بارگذاری طرح به‌صورت قطعه‌ای و تراکنشی است تا محدودیت CursorWindow مانع ویرایش نشود؛ schema همچنان ۲ است.
- در ردیابی سه‌بعدی، pitch مرجع ثابت تا ۴۰ درجه پذیرفته می‌شود؛ حد pitch تصویر زنده ۳۰ درجه و حد yaw هر دو ۴۰ درجه است. کنترل عمق، سطح و تطابق نقاط برقرار است. این حدود مهندسی، ادعای دقت بالینی نیستند.

## تصمیم: نمایش زندهٔ طرح — ۲۰۲۶/۱۱/۰۸

طرح ذخیره‌شده با نقاط صورت در دوربین تطبیق داده می‌شود؛ خط‌چین برای بررسی، با تطبیق معتبر ظاهر می‌شود؛ نمایش پیوسته پس از پایداری نقاط و تأیید کاربر است. نسخهٔ فعلی ردیابی سه‌بعدی سبک با سطح تقریبی پیشانی و کنترل کیفیت دارد؛ اسکن سه‌بعدی، شناسایی هویت و کالیبراسیون میلی‌متری در آن وجود ندارد. با افت انطباق، خط و نقاط کمرنگ و تأیید پاک می‌شوند؛ با قطع ردیابی یا اختلاف شدید، خط پنهان می‌شود. ارزیابی دقت پیش از کاربرد علامت‌گذاری باز است؛ [سند 10](10-LIVE-PLAN-GUIDE.md).
